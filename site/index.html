OpenLint, release by release

Median time to lint each document with the same ruleset (spectral:oas). Each release is compared with the one before it; a change of more than 10% is highlighted.

Alongside other linters

The latest release of each tool on the same documents. OpenLint, Spectral, vacuum and the IBM validator run the same spectral:oas ruleset; Redocly can't read it and runs its own recommended rules. Each tool implements the rules its own way, so the problem counts differ: compare the times as a guide, not a race.

The documents

Each is pinned to a commit in the provider's own repository, and downloaded at run time, so every run lints identical bytes. Want your API included? Open a pull request adding it to corpus.yaml.

How it's measured

  • Each tool runs from the command line, as users run it: the time includes starting the tool. Output goes to a file.
  • One untimed warm-up, then 5 timed runs for documents under 2 MB and 3 for larger ones. The table shows the median; peak memory is the largest resident set size seen.
  • All releases run on the same machine in the same run, so comparisons between releases are fair. Absolute times depend on the machine, which is shown above.
  • A run that takes more than 10 minutes is stopped and shown as a timeout.
